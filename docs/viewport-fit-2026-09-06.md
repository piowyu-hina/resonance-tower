# 桌面固定畫布：16:9

## 結構

正常入口不變：`prototype/index.html?debug`。

`index.html` → `#viewportStage` → 同源 iframe `game.html`（1600×900）。

原 index.html 的完整遊戲 DOM 搬至 game.html，沒有重寫場景、劇情或戰鬥。外層只處理大小、置中與留邊；查詢參數與 hash 原樣交給內頁。內頁可以直接開啟作為舊版邏輯視窗的檢查入口。

縮放比例為 `min(可用寬度 / 1600, 可用高度 / 900)`。以 1600×900 作為正式邏輯基準，取代初期 1440×1000 實驗。

五個主要場景的可見外框統一為 1536×864（16:9），畫布左右各留 32、上下各留 18。尺寸集中於 `embedded-game.css`，避免切換場景時一寬一窄。村莊不再使用加高 cover 實驗的左右裁切／互動層偏移；原 1672×941 素材保留。戰鬥上／下留白改為 130／150，讓互動區與技能列不重疊。遠征準備另製寬構圖背景，原 3:2 資產不刪除。

## 為什麼用內嵌視窗

單純把原 DOM 包在 transform 裡，內部 vw/vh 與 media query 仍跟著外層視窗改變，且 fixed 元件與 getBoundingClientRect 的定位可能混用兩套座標。

內嵌視窗提供真正固定的 CSS viewport。瀏覽器負責換算縮放後的指標事件，原有 tooltip、選單、拖曳與動畫可維持內部座標。ResizeObserver 只改 iframe 的呈現比例，不重設 src、DOM、戰鬥或劇情狀態。

## 範圍與取捨

- 外層和內頁文件不捲動；主要版面在邏輯視窗內完整顯示。
- 手記目錄、背包等內容仍能局部捲動。背包的關閉列在捲動時保持可見。
- 16:9 視窗完整利用畫布；其他比例置中留邊，文字跟隨整體縮放，並非自動放大字體的響應式排版。
- 全畫面動畫覆蓋遊戲畫布，不延伸到外層留邊。
- 不處理手機、極端尺寸；不以這次修改宣稱修復所有素材本身或遮罩切邊。
- 未改首領演出設計、戰鬥數值、劇本、玩家待製作的狀態圖。

## 驗收

`node tests/ui-regression.test.js --resize-only`：

- 1280×720、1366×768、1440×900、1920×1080。
- 村莊、家、遠征入口／準備、戰鬥、培養、商店、背包、手記。
- 主畫布四邊不超出視窗、比例固定 16:9、五個主要場景均為 1536×864、文件無溢出。
- 同一遊戲實例連續改變尺寸，內部視窗固定、狀態標記保留。
- 實際點擊培養開關、戰鬥紀錄及滑鼠技能說明。
- 滾輪捲動手記長目錄和背包長清單，外層不跟著捲動。
- 首領動畫播放期間切換尺寸，演出正常結束並回到 combat。

完整回歸仍驗證 game.html 的原有功能；外層整合測試也加入完整套件。視覺檢查工具 `tests/ui-review.mjs` 保留針對邏輯畫布的原尺寸檢查，縮放截圖由 `--resize-only` 產生於 `test-results/resize-*.png`。
