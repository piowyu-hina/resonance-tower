# 戰鬥 UI 重製 — 2026-09-06

## 方向

把角色與魔物放回同一個場景，保留玩家的新 Q 版與技能畫風。畫面以角色、美術與戰況為主，操作固定在底部，不把戰鬥紀錄當成常駐主視覺。

使用既有 `slime_forest_battle.png`、`ruins_battle.png`，沒有生成新圖片，也沒有修改、刪除或提交玩家正在整理的圖片。

## 實作

- 新增獨立 `prototype/styles/combat-scene.css`，桌面啟用；窄畫面沿用既有堆疊結構，未更動 viewportStage／縮放架構。
- 我方完整 Q 版、生命／行動進度、58px 自動技能；敵方一般技能 42px、首領技能 48px。技能冷卻顯示剩餘整秒，不改實際計時。
- 底部專屬技能按鈕含 70px 圖示、技能名、可用狀態；藥水與被動護符分區。空槽仍保留，既有裝備與施放限制不變。
- 首領場地與血條／技能分離，保留四枚岩刺點擊及原本傷害判定。黏液目標增大，生成位置改讀取實際尺寸，避免貼邊脈動裁切；可以滑鼠或鍵盤擊破。
- 移除舊肖像矩形內陰影，受擊以短暫亮度閃爍呈現；傷害、治療與 PERFECT 數字加大。小初守護回饋使用橢圓光環。
- 戰鬥紀錄由右上角按鈕展開，資料仍完整累積。勝利／敗北覆蓋期間保留場景尺寸。
- 延續 0.2 秒、4px 的場景進場動態。首領出場、護符碎裂、天堂往返及對話內容均未修改。

## 驗證

新增 `node tests/ui-regression.test.js --combat-ui-only`，納入完整 UI 回歸：

- 1440×1000、1280×900 的操作列、角色資訊、首領／兩隻召喚物、場地不互相重疊；無水平溢出。
- 完整角色圖、我方／敵方技能秒數、鍵盤技能說明、小初實際施放與冷卻。
- 黏液尺寸與位置、滑鼠與鍵盤完成同一批機制。
- 三隻小怪、史萊姆王、遺跡之主未知等級／隱藏 HP／可見行動條。
- 勝敗狀態不改變戰場尺寸。

完整單元測試及瀏覽器回歸另覆蓋遠征、首領準備、遺跡四枚岩刺傷害、死亡與女神、手記、小初相遇到契約，以及家／商店／角色培養。
